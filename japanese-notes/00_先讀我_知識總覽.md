# 日文課堂筆記產生專案：知識總覽（新對話請先完整讀完本檔）

全程使用繁體中文回覆。使用者偏好：口吻自然、不要「結論／建議」式的公式化標題；資料不足時主動請使用者補充，不自行模擬資料；成本敏感，未經同意不啟動子代理、不做大量處理。

---

## 1. 目標與輸入輸出

- 輸入：一堂日語課的帶時間戳逐字稿（.srt，中文為主夾日文，語音辨識品質差，沒有說話者標記）。
- 輸出：與範本講義「同樣撰寫邏輯、同樣版面」的筆記，格式為可編輯的 Word（.docx）。
- 做法：模型負責內容（三階段），程式 `build_note.py` 負責版面。不要再發明任何自創標記格式給最終成品，成品形式一律以範本為準。

## 2. 三階段（不得自行跨階段）

每次只做一個階段，完成後停下來等使用者確認。
1. 整理：只列「要收進筆記的項目清單」，每項標類型（課外補充／單字／文型／例文／會話／小文章／練習）、逐字稿時間範圍、一句話主題。列出不收錄的段落（閒聊、雜音）。不寫內容。
2. 撰寫：依確認過的清單逐項寫內容，形式比照範本（詞卡、表格、短句＋一行中文）。
3. 組版：把內容寫成 note.json，執行 build_note.py 產生 .docx，轉 PDF 看圖檢查後交付。

## 4. 撰寫邏輯（從範本歸納）

- 單元順序：每課先「課外補充」（老師補充、課本沒有的），再依課本順序：單字 → 文型＆例文 → 會話 → 小文章 → 練習。
- 精簡：這是複習筆記，不是課堂紀錄。不敘述老師說了什麼、不逐段摘要、正文不放時間戳。
- 單字詞卡：一詞一格（每格寬約版心 1/3，一列最多 3 格）。內容只有「詞（漢字上方讀音）＋藍色中文」，下方配插圖。動詞與片假名外來語務必收錄（N4 以上動詞、片假名外來語是重點）。
- 文型固定流程：模板 → 一個代表例句 → 編號注意事項 → 變化 → 練習；沒有的環節省略。
- 成對概念（くれる／もらう、自動詞／他動詞、較正式／較口語）：並排成兩欄表格。
- 課堂實例：老師當場舉的例句保留。
- ○補：課本沒有、老師口頭補充的項目，前標「○補」。
- 橘色＊註解只有三種用途：用法限制、語感差異、發音連音；內容必須是老師講過的，一句話。
- 助詞重點：教學目標的助詞（例：で／に／を 的對比）加淺黃色螢光。
- 中文翻譯：台灣口語，藍色手寫體。
- 錯誤處理：老師口誤或辨識錯字，正文寫更正後的日文，「原辨識→更正」列入文末待確認清單。
- 不確定的內容：不寫進正文、正文也不加「待確認」字樣，一律只列在文末【待確認清單】（位置｜問題｜需要補充什麼）。

## 5. 版面規格（量自原版 PDF）

- A4 直式 595×842pt；左右邊界 54pt（版心約 487pt）。
- 頁首：左「L24 單字」類、右日期「2026.04.01」，Calibri／微軟正黑體 10pt 灰 #767171；頁尾置中頁碼。
- 標題「課外補充」18pt 粗，源石黑體 M；子標籤「單字」16pt，淺黃底 #FFE699。
- 日文本文：黑體 UI（日本語）14pt；讀音 8pt。
- 中文：清松手寫體1 12pt，藍 #0070C0。
- 表格：框線淺灰 #E8E6E6；表頭底色淺藍 #DEEAF6，置中 12pt；左欄詞也用淺藍底。
- ＊註解：橘色（約 #C55A11）。
- 聲調紅線：#FF7D80，約 0.72pt。

## 6. 聲調知識

完整規則見本包 pitch/：`音調紅線閱讀規則.md`（使用者原文）、`日語句子拆解_語音片段與接續文字.md`（拆句規格）、`japanese-pitch-reader/SKILL.md`（統一標記與判讀流程，含 scripts/pitch_lines.py）。使用者帳號已安裝此 skill（anthropic-skills:japanese-pitch-reader）。

重點摘要：
- 統一標記（單字、例句同一套）：`型（號數）：每拍高低`。號數＝下降發生在第幾拍之後；0 平板、1 頭高、1<n<拍數 中高、n＝拍數 尾高。
- 拍：小寫ゃゅょ併入前一拍；っ、ん、ー 各一拍。
- 紅線：水平線＝該拍高；右側下降角＝「這拍高、下一拍低」。簡化呈現要依規則補回。完全沒有線＝待確認，不可當平板。
- 平板與尾高詞末都高，差在後接助詞：平板後助詞高，尾高後助詞低。
- 拆句：語音片段（實詞，各自有聲調）＋接續文字（は が を に へ で と の も から まで より か，跟隨前一片段：平板後高、有下降後低）。顯示歸屬在前一片段後（年を｜取る）。は 讀 わ、へ 讀 え。標點是邊界。不明就標待確認，不猜。
- 對照資料（L24 單字 2026.04.01 第 1 頁，號數由紅線讀出、未對照字典）：アヒル 0；ガチョウ 0；ガチョウ肉 2；働く 0；勤める 3；務める 3；ころころ 1；ごろごろ 1；コロコロ（黏塵滾輪）0。例句拆解結果見 pitch/page1_sentence_segments.md。
- 現階段規則（使用者指定）：逐字稿沒有聲調資料，筆記中所有詞一律先以 0 號音繪製；未來由 schema／MCP 提供號數後替換重產。待確認清單第一行要註明這點。
- 聲調資料來源候選：使用者自建的「日文聲調編輯台」https://jp.hikorin.com/japanese-author.html （規則＋模型產生，輸出圖片，結果需核對）；使用者打算包成 MCP。app.jaccent.net 被 robots.txt 擋，不要繞過。字典結果遇到老師說「兩種都可以」的詞要標待確認。

## 7. 產生器 build_note.py（附在 builder/）

`python3 build_note.py note.json out.docx`，再 `soffice --headless --convert-to pdf out.docx` 轉圖檢查。
- 聲調線做法：每拍一個表格小格（Word 原生、可編輯）。上方讀音列的上緣紅線＝高音，右緣紅線＝下降。漢字整段合併成一格放在讀音下方。
- 日文行寫法：片段用「／」分隔；`{漢字|讀音}`；`+助詞`（讀音不同寫 `+は=わ`）；`#n` 指定號數（`#null` 不畫）；`!、` 標點；`@A：` 標籤。
- 區塊類型：title、tag、cards（illust 可為 null／關鍵字字串／{source,title,url[,image]}；有 image（圖片網址或本機路徑）就嵌入圖片，網址下載後快取在 images/，下載失敗退回文字佔位框）、defs、sentences（可帶 bullet 如 "A："）、note（＊註解）、pending（待確認頁）。
- 範例資料：note_L33_trial.json；成品 L33_trial.docx（GitHub repo kevin9812158/- 的 japanese-notes/，分支 claude/conversation-reading-ability-2xqqh1）。
- 已知限制：此環境沒有原版字型，LibreOffice 轉出的圖會用替代字型；長句可能超過欄寬。

## 8. 插圖規則（使用者指定）

- 預設只用いらすとや；查不到才用其他可免費使用的圖，並在框內與待確認清單註明來源；使用前先查該站使用規範。
- 動詞與抽象詞不配圖（比照原版）。照片類（店家照、來源不明圖）不要用。
- いらすとや 規約重點：個人、商用、非商用免費；不需標出處；商用每件作品 20 張以內（超過每張 1,100 日圓且全部計費）；禁止以插圖為主體再散布。
- 搜尋：WebFetch `https://www.irasutoya.com/search?q=關鍵字` 可取得圖名與頁面網址。
- 下載：需要雲端環境網路設為 Custom 並允許 www.irasutoya.com、blogger.googleusercontent.com、1–4.bp.blogspot.com（在 claude.ai/code 的環境設定）。如仍被擋，用 `curl -sS "$HTTPS_PROXY/__agentproxy/status"` 看被擋的主機名，請使用者補上。add_illust 已支援嵌入圖片（2026.10.08 測試成功）。
- 找圖片網址：在文章頁 HTML 找 blogger.googleusercontent.com 的 /s1600/ 圖檔；不要用 og:image（裁切過的縮圖）。

## 11. 曾經犯過、不要再犯的錯

- 發明自創標記當成品格式、範例欄位留空，導致成品長得不像原版。
- 把正文寫成課堂摘要（時間戳、經過、零碎待確認）。
- 單字放在課外補充之前。
- 憑電子郵件網域誤判使用者為組織帳號（使用者是個人版）。
- 試圖用其他方式繞過被網站擋住的讀取。
- Claude App 的檔案預覽不會解析 .docx，會顯示成亂碼；交付時另附 PDF 預覽。
