# 日文課堂筆記產生專案：知識總覽（新對話請先完整讀完本檔）

流程已整理成 skill：skill/japanese-class-notes/（打包檔 japanese-class-notes.skill）。改了產生器或規則時，記得同步更新 skill 內的 scripts/build_note.py 與 references/ 再重新打包。

全程使用繁體中文回覆。使用者偏好：口吻自然、不要「結論／建議」式的公式化標題；資料不足時主動請使用者補充，不自行模擬資料；成本敏感，未經同意不啟動子代理、不做大量處理。

## 1. 目標與輸入輸出

- 輸入：一堂日語課的帶時間戳逐字稿（.srt，中文為主夾日文，語音辨識品質差，沒有說話者標記）。
- 輸出：與範本講義「同樣撰寫邏輯、同樣版面」的筆記，格式為可編輯的 Word（.docx）。
- 做法：模型負責內容（三階段），程式 `build_note.py` 負責版面。不要再發明任何自創標記格式給最終成品，成品形式一律以範本為準。

## 2. 三階段（不得自行跨階段）

每次只做一個階段，完成後停下來等使用者確認。
1. 整理：只列「要收進筆記的項目清單」，每項標類型（課外補充／單字／文型／例文／會話／小文章／練習）、逐字稿時間範圍、一句話主題。列出不收錄的段落（閒聊、雜音）。不寫內容。
2. 撰寫：依確認過的清單逐項寫內容，形式比照範本（詞卡、表格、短句＋一行中文）。
3. 組版：把內容寫成 note.json，執行 build_note.py 產生 .docx，轉 PDF 看圖檢查後交付。

## 4. 撰寫邏輯（從範本歸納）

- 單元順序：每課先「課外補充」（老師補充、課本沒有的），再依課本順序：單字 → 文型＆例文 → 會話 → 小文章 → 練習。
- 精簡：這是複習筆記，不是課堂紀錄。不敘述老師說了什麼、不逐段摘要、正文不放時間戳。
- 單字詞卡：一詞一格（每格寬約版心 1/3，一列最多 3 格）。內容只有「詞（漢字上方讀音）＋藍色中文」，下方配插圖。動詞與片假名外來語務必收錄（N4 以上動詞、片假名外來語是重點）。
- 文型固定流程：模板 → 一個代表例句 → 編號注意事項 → 變化 → 練習；沒有的環節省略。
- 成對概念（くれる／もらう、自動詞／他動詞、較正式／較口語）：並排成兩欄表格。
- 課堂實例：老師當場舉的例句保留。
- ○補：課本沒有、老師口頭補充的項目，前標「○補」。
- 橘色＊註解只有三種用途：用法限制、語感差異、發音連音；內容必須是老師講過的，一句話。
- 助詞重點：教學目標的助詞（例：で／に／を 的對比）加淺黃色螢光。
- 中文翻譯：台灣口語，藍色手寫體。
- 錯誤處理：老師口誤或辨識錯字，正文寫更正後的日文，「原辨識→更正」列入文末待確認清單。
- 不確定的內容：不寫進正文、正文也不加「待確認」字樣，一律只列在文末【待確認清單】（位置｜問題｜需要補充什麼）。

### 4.1 取捨習慣（2026.10.08 逐頁看範本歸納）

- 課本單字編號（2. 3. …），老師補的前標圓圈「補」，相關的成對詞並排一列（直す／直る、連れて行く／連れて来る、持って行く／持って来る）。
- 動詞：「辭書形・ます形＋中文」，例句直接放在同一格裡用 • 列出，不另開表格。名詞、片假名外來語：詞卡＋插圖，例句放在詞卡下方用 • 列出（無表格）。
- 課外補充的固定組合：詞卡 → 一個「「XX」的說法」主題表（兩欄對比，例：較正式／較口語；或左欄詞＋中文、右欄例句，例：擬聲擬態語、「工作相關」的日文）→ 灰色表頭的「短句練習」表。
- 同主題的零散內容會併成一張表，不會按課堂順序拆成好幾段。
- 老師舉的例句幾乎全收（年を取ってから… 收 6 句），但每句只配一行短中文。
- 練習：只收句子本身（短句練習），不收課堂操作（兩兩對話、換算遊戲、A／B 角色）。
- 語感差異的補充常寫在中文後面，用橘色「→口語：朋友、親人間常用」這種短箭頭，不一定另起＊行。

## 6. 聲調知識

完整規則見本包 pitch/：`音調紅線閱讀規則.md`（使用者原文）、`日語句子拆解_語音片段與接續文字.md`（拆句規格）、`japanese-pitch-reader/SKILL.md`（統一標記與判讀流程，含 scripts/pitch_lines.py）。使用者帳號已安裝此 skill（anthropic-skills:japanese-pitch-reader）。

重點摘要：
- 統一標記（單字、例句同一套）：`型（號數）：每拍高低`。號數＝下降發生在第幾拍之後；0 平板、1 頭高、1<n<拍數 中高、n＝拍數 尾高。
- 拍：小寫ゃゅょ併入前一拍；っ、ん、ー 各一拍。
- 紅線：水平線＝該拍高；右側下降角＝「這拍高、下一拍低」。簡化呈現要依規則補回。完全沒有線＝待確認，不可當平板。
- 平板與尾高詞末都高，差在後接助詞：平板後助詞高，尾高後助詞低。
- 拆句：語音片段（實詞，各自有聲調）＋接續文字（は が を に へ で と の も から まで より か，跟隨前一片段：平板後高、有下降後低）。顯示歸屬在前一片段後（年を｜取る）。は 讀 わ、へ 讀 え。標點是邊界。不明就標待確認，不猜。
- 對照資料（L24 單字 2026.04.01 第 1 頁，號數由紅線讀出、未對照字典）：アヒル 0；ガチョウ 0；ガチョウ肉 2；働く 0；勤める 3；務める 3；ころころ 1；ごろごろ 1；コロコロ（黏塵滾輪）0。例句拆解結果見 pitch/page1_sentence_segments.md。
- 現階段規則（使用者指定）：逐字稿沒有聲調資料，筆記中所有詞一律先以 0 號音繪製；未來由 schema／MCP 提供號數後替換重產。待確認清單第一行要註明這點。
- 聲調資料來源候選：使用者自建的「日文聲調編輯台」https://jp.hikorin.com/japanese-author.html （規則＋模型產生，輸出圖片，結果需核對）；使用者打算包成 MCP。app.jaccent.net 被 robots.txt 擋，不要繞過。字典結果遇到老師說「兩種都可以」的詞要標待確認。

## 7. 產生器 build_note.py（附在 builder/）

`python3 build_note.py note.json out.docx`（正式檔）；預覽用 `python3 build_note.py note.json preview.docx --preview` 再 `soffice --headless --convert-to pdf preview.docx` 轉圖檢查。
- 讀音與聲調線做法（2026.10.08 改版，使用者指定要用 Word 內建 ruby、遵守 JIS X 4051／W3C JLReq）：
  - 讀音：w:ruby。熟語ルビ逐字對應（JSON 寫 {割|わり}{引|びき}，熟字訓才整組），ルビ 7pt＝親字 14pt 的 1/2，置中；ルビ比親字長時親字兩側加空。日文段落開禁則，關閉中日／英數自動加空（讓字位可預測）。
  - 紅線：和原版一樣是另外畫的線條圖形（原版 PDF 的紅線是向量線段，不是文字格式）。程式依字寬算每拍位置（Yu Gothic UI 全形 1.026em、數字 0.601em，取自原版 PDF 嵌入字型），水平相對行首字元、垂直相對行頂；日文行固定行高 25pt（LINE_H，對齊範本 23–26pt）。可調參數：PITCH_Y、PITCH_DROP、LINE_H、TAB_X。
  - 限制：在 Word 裡改字後紅線不會跟著移動，要改 note.json 重新產生。LibreOffice 預覽要加 --preview（換成 IPAGothic 與其字寬），正式檔不要加。
  - 待使用者在 Word 確認：Word 的ルビ／行高排法和 LibreOffice 可能不同，紅線若上下或左右偏，回報後調整上述參數。
- 日文行寫法：片段用「／」分隔；`{漢字|讀音}`；`+助詞`（讀音不同寫 `+は=わ`）；`#n` 指定號數（`#null` 不畫）；`!、` 標點；`@A：` 標籤。
- 區塊類型：
  - title、tag（黃底子標籤，例「單字」）、note（＊註解）、pending（待確認頁）。
  - cards：詞卡，per_row 預設 3（動詞等長詞用 2）；card 可帶 label（課本編號 "2." 或 "補"，"補" 會加框）、arrow；illust 為 null／關鍵字字串／{source,title,url[,image]}，有 image 就嵌入圖片（網址快取在 images/，失敗退回文字框）。
  - bullets：表格外的 • 例句（範本：詞卡下方的例句），中文接在後面，放不下自動換行。
  - defs：主題表。row 有 examples 時為三欄「詞｜例句｜中文」（左欄跨列，可帶 term_sub 中文、arrow 語感）；否則兩欄（zh 或 jp_list）。
  - grid：對照表（表頭＋欄名＋資料列，儲存格 {"jp"}、{"zh"} 或字串），例「幾折」的說法。
  - sentences：兩欄句子表，practice: true 為灰色表頭（短句練習）；row 可帶 bullet（"A："）、arrow。
- 範例資料：note_L33.json；成品 L33.docx（GitHub repo kevin9812158/- 的 japanese-notes/，分支 claude/conversation-reading-ability-2xqqh1）。
- 已知限制：此環境沒有原版字型，LibreOffice 轉出的圖會用替代字型。
- 版面陷阱：頁面上相鄰的表格會被合併（add_jp_line 已在每行後補極小段落）；「儲存格裡的巢狀日文行＋中文欄」在 LibreOffice 會被壓縮，所以例句表一律讓中文獨立成外層表格的一欄。

## 13. 版面密度調整（2026.10.08 分析；使用者要求一次改一頁）

進度：第 1 頁已調整並經使用者驗證（插圖放大、不放出處、行距 25pt、儲存格邊距 1pt、表頭與對照表不拆頁）。其餘各點待後續頁面處理。

使用者的兩條要求：
1. 插圖不放引用出處（見第 8 節）。
2. 每頁資訊密度要和範本一致。

量測（範本 5 份 28 頁 vs. L33 預覽 4 頁；填滿＝內容最低點占版心高度）：
- 範本純文字頁：約 42–48 行、600–900 字、填滿 93–100%。插圖頁：12–18 張圖、填滿 83–96%。
- 範本只有在一個大段落結束時才留白（例：4/08 p2 課外補充結束只到 60%，下一頁從「大家的日本語 L24」開始；4/15 p5 37%），其餘頁都排滿。
- 範本日文行（含ルビ）的行距中位數 23–26pt；L33 是 28–35pt，約鬆 35%。
- L33：p1 36 行／307 字、p2 31 行／377 字（墨量 4.9%，範本文字頁約 6–10%）、p3 只到 20%、p4 是待確認清單。

造成密度不足的原因：
- 日文行固定行高 32pt＋儲存格上下邊距，比範本高。範本約 24–26pt 一行（ルビ＋本文）。
- 詞卡：範本列高約 137pt，圖約 100pt 寬、填滿格子；L33 列高約 157pt，圖只有 84pt，下面還多一行出處連結。
- 「打折」的說法：每個例句一列、每列約 40pt；範本同類表（擬聲擬態語）約 27pt 一列。
- 「幾折」對照表：每列只有一兩個短詞，卻占一整列約 40pt，空白多；而且表頭被留在 p1 底、內容跑到 p2（範本不會把表頭和內容拆開）。
- 單字區：割引 詞卡在 p2，例句和＊註解掉到 p3，被拆開。範本動詞的例句放在同一格，詞和例句不分頁。
- 中文換行：短句練習的長中文（含 → 補充）在右欄折成三行，把列撐高。

之後調整的方向（待使用者同意再改）：
- 日文行距降到約 24–26pt，縮小儲存格上下邊距；在 Word 確認ルビ不被切到。
