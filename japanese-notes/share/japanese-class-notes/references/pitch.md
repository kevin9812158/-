# 聲調

要判讀原版講義上的紅線、做拆句時，有安裝 `japanese-pitch-reader` skill 就用它，沒有就照下面的規則。這裡只放筆記產生需要的重點。

## 目前規則（使用者指定）

- 還沒有聲調資料的詞，一律先畫成 0 號音（平板），也就是 note.json 的 `accent_default: 0`，並在待確認清單列一條【高】。
- 聲調資料來自 JAPANESE UP 聲調 MCP（見下方「MCP 聲調資料」），拿到後把號數填進 `#n` 再重新產生。

## 標記

- **統一標記**（單字、例句通用）：`型（號數）：每拍高低`。號數＝在第幾拍之後下降。
  - 0：平板
  - 1：頭高
  - 1 < n < 拍數：中高
  - n＝拍數：尾高
- **怎麼數拍**：小寫的ゃゅょ併入前一拍；っ、ん、ー 各算一拍。
- **紅線的意思**：
  - 水平線＝該拍是高音。
  - 右側的下降角＝「這拍高、下一拍低」。
  - 範本上有時會簡化畫法，要依規則補回。
  - 完全沒有線＝待確認，不可以當成平板。
- **平板和尾高**：兩者詞末都是高音，差在後面接的助詞：平板後的助詞是高音，尾高後的助詞是低音。

## 拆句

- **語音片段**：實詞，各自有聲調。
- **接續文字**：は が を に へ で と の も から まで より か。跟著前一個片段走：前一段是平板，助詞就高；前一段有下降，助詞就低。
- **顯示**：接續文字歸在前一個片段後面，例如「年を｜取る」。
- **讀音**：は 讀 わ，へ 讀 え。
- **邊界**：標點是片段的邊界。
- 判斷不出來就標待確認，不要猜。

## 對照資料

從使用者範本的紅線讀出號數，整理成對照表，例如 `{"勤める": 3, "ガチョウ肉": 2}`。存成 JSON 後給 `scripts/mcp_pending.py --ref` 使用，做抽樣比對。號數要標明出處（哪份範本第幾頁），並註明是否對照過字典。

## MCP 聲調資料（JAPANESE UP！聲調查詢）

連接器的設定見 `references/setup.md`；新增後要開新的工作階段才會載入。

**使用前**
- 先用 getPronunciationCollaborationStatus 確認同意狀態是 current。
- 查詢內容會在伺服器保存 90 天，供本人追溯與服務擁有者校訂；不要送機密或他人個資。

**查詢**
- 新的詞、句子用 analyzeJapanesePronunciation。課本題庫裡已有的詞用 getAuthorizedPronunciations。
- 少量查詢就好，不要整份逐字稿丟進去。
- 不要自行補齊未知的聲調，原始 JSON 照實保留。

**回傳欄位**
- `tokens[]`：詞法單位，は、から、ます 也會單獨成一個 token。每個 token 有：
  - `surface`
  - `reading`：整詞讀音，沒有逐字對應熟語ルビ，逐字切分由我們處理。
  - `moras`
  - `marks`：每拍的高低。0＝低，1＝高，2＝高且為該詞最後一個高拍。2 後面是否真的下降，平板和尾高的差別還要看片語層級，定義待伺服器確認。
  - `accent`：號數，可能是 null。
  - `status`：目前都是 predicted。
  - `warnings`：例如 phrase_accent_unresolved。
- 整筆查詢另有 `needsReview`、`reviewStatus`（目前都是 unreviewed）和 `warnings`。

**已知限制（2026 年 10 月測試）**
- 單字的結果大多可以直接用。
- 句子還不夠：
  - 整句的 accent 都是 null。
  - 助詞一律回傳 0（「割引は」的 は 應該是高）。
  - 複合詞會被拆開（例：八時、ガチョウ肉）。
  - 同一個詞放在句中和單獨查，結果可能不同，而且不一定帶警告。
  - 數字與漢字讀音可能猜錯（例：二割 讀成 ふたわり、何時 讀成 いつ）。

**轉成筆記**
1. 先用 `getCurrentGptUser` 看使用者被授權的班級，選這堂課對應的班級，再用 `getAuthorizedPronunciations` 查課程題庫。查不到會回 `not_found`，不會自動改成分析。
2. 題庫沒有的，把筆記每一行日文的純文字逐行丟給 `analyzeJapanesePronunciation`。把原始回傳存成陣列檔，每行一筆，`text` 就是該行的純文字。
3. 執行 `python3 scripts/mcp_apply.py note.json mcp結果.json 輸出note.json 不一致清單.json`：
   - 筆記的讀音和 MCP 逐拍一致時，在每個語音片段後寫入 `#m:` 逐拍高低。
   - 讀音不一致的行維持 0 號音，記在不一致清單（例：何 なん／なに、大 だい／おお、二 に／ふた）。
   - 不自行補齊：助詞等 MCP 回傳 0 的拍照實畫成低。
4. 不一致清單的每一行列【高】，並和同一行的 MCP 項目合成一條。

**審閱台（建議的方式）**
- 「聲調審閱台」頁面：每個人用自己的一份。先用 Artifact `list` 找標題「聲調審閱台」；沒有就發布 `assets/pitch-review.html`（`capabilities: {"db": {}}`），步驟見 `references/setup.md`。不要使用別人的審閱台網址。
- 每條項目一張卡片，依風險排序：日文、中文、依據，以及畫在讀音上的紅線。
- 使用者的操作（使用者指定要最快的互動，不要模式、號數按鈕或多個欄位）：
  - **點一拍**：依「音調紅線閱讀規則」，這個片段改成「在這拍之後下降」，其他拍自動設定：首拍低、2 到該拍高、之後低；點第一拍＝頭高；點最後一拍＝尾高（記為 2）。再點同一拍改回平板 [0]。
  - **拖曳反白**（手機：長按一拍再滑）：選到的幾拍自成一個片段，前後切開、中間合併。例：いちわりびき 選 わり → いち｜わり｜びき。有標點的分界不會被合併。可以切在漢字讀音中間，套用回 note.json 時由 Claude 處理（例如改寫ルビ切法）。
  - **右鍵點一拍**（電腦；手機的長按是反白切分，不當右鍵）：整個片段切換為 GAP（接續文字），只用灰色表示，前面不放分隔符號（使用者指定，「＋」不好讀）。GAP 片段一樣用左鍵設聲調，但多一個「沒有線（全低，[－]）」：同一拍一直點＝在這拍下降 → 平板 [0] → 沒有線 → 在這拍下降。
  - **正確**、**其他問題**（一個自然語言輸入框，寫字、讀音、翻譯錯誤，由 Claude 代勞）。
- 結果存在 `batches/<批次>/reviews/<編號>`，內容是 {status, line:[{m 0/1/2, gap, br}], instruction}。gap＝這拍屬於 GAP 片段，套用回 note.json 時寫成前一片段的 `+接續文字`。line 和項目攤平後的拍一一對應；br＝前面是片段分界（使用者切分後會改變），m＝2 是片段最後一拍的尾高下降。
- 新的一課：
  1. `python3 scripts/review_export.py note.json mcp結果.json > items.json`。每條帶 source（note.json 原行）、units（同一個漢字的ルビ是一個單位）、after（片段後的標點）。
  2. 用 ArtifactData 的 batch 寫入 `batches/<批次>`（{title, createdAt}）和 `batches/<批次>/items/<編號>`。
  3. 請使用者打開頁面。
- 使用者說審好了：
  1. 用 ArtifactData 讀 `batches/<批次>/reviews`。
  2. 執行 `python3 scripts/review_apply.py note.json items.json reviews資料夾 輸出note.json`（reviews 用 ArtifactData list 加 out_dir 存下來）。每個審閱台片段寫成一個語音片段，各自畫線，和頁面顯示一致；GAP 片段也獨立成段，不併進前一段，避免多畫下降角；切在數字讀音中間時逐字拆開重配讀音。殘留的不合規則高低（例如下降後又有一拍高），照該片段號數整理，並告訴使用者。
  3. 執行 instruction（字、讀音、翻譯的更正）。
  4. 重新產生 Word，列出改了哪些條目。
  5. 要回報給 MCP 的修正，逐筆經使用者同意。
- 存檔不能用時，頁面底下有「複製回覆文字」，貼到對話即可。

**審閱流程（在對話中進行，不放在 Word 裡）**（審閱台不能用時的備案）
1. 執行 `python3 scripts/review_list.py note.json mcp結果.json`，產生風險分流對照表，**直接貼在對話裡**讓使用者選填。
   - 每一條有：編號、風險、日文、讀音（依語音片段，用｜分隔）、中文、目前聲調、依據。
   - 目前聲調同時給兩種寫法：每個片段的 [N] 號數，以及 NHK 辭典式的下降標記（＼ 寫在下降前那一拍的後面）。
   - 排序：讀音和 MCP 不一致 → MCP 有警告或號數未解 → MCP 無警告。所有項目都列出，沒有警告的也照樣列，因為沒有警告不代表正確。
2. 使用者回覆的方式，三種都要接受：
   - 指定片段改幾號：「12 的 いますか 改成 2 號」。
   - [N]：「12 [1] [0] [2]」，依片段順序；只給一個時，代表整行只有一個片段。
   - NHK 式：「12 い＼ま｜わりびきして｜いま＼すか」；沒有 ＼ 代表平板。
   - 也可以改讀音：「2 讀 おおわりびき」。
   - 沒提到的條目，視為維持現狀。
3. 依回覆改 note.json：該片段改寫成 `#n` 或 `#m:`，重新產生 Word，並把改過的條目列出來給使用者確認。
4. 用 `scripts/mcp_pending.py` 判斷等級：有 warnings、accent null 或 needsReview → 高；和範本或已知資料不一致 → 高；同一個詞（含漢字或片假名）在不同查詢的 marks 不一致 → 高。可以加 `--ref` 放範本紅線讀出的號數，做抽樣比對。
5. Word 的待確認清單只放內容類的項目（辨識錯字、未收錄、編號等），聲調只放一條【高】總說明（例如「紅線依 MCP 預測，尚未審閱」）。逐條審閱都在對話中進行。

**回饋修正**
- 審閱後的修正要經使用者逐筆同意，才用 submitPronunciationFeedback 送回伺服器。
- 送之前先列出要送的修改內容和用途。
- 只送相關的修正和依據，不送整段對話。
- 沒有同意的就保持未回報。
- 有警告的項目，就是要審的清單。
