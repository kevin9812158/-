# 版面規格與密度

## 規格（量自原版 PDF）

- **紙張**：A4 直式 595×842pt，左右邊界 54pt，版心約 487pt。
- **頁首**：左邊是「L33 單字」這類單元名，右邊是日期「2026.10.07」，Calibri 10pt 灰 #767171。頁尾置中放頁碼。
- **標題**：「課外補充」「大家的日本語 L??」用源石黑體 M 18pt 粗體。子標籤（單字、文型＆例文…）16pt，淺黃底 #FFE699。
- **日文**：Yu Gothic UI 14pt。原版 PDF 嵌入的字型名稱是「..黑體UI-日本語」，字寬是全形 1.026em、數字 0.601em。
- **ルビ**：7pt，即本文的 1/2。
- **中文**：清松手寫體1 12pt，藍色 #0070C0。
- **表格**：框線淺灰 #E8E6E6；表頭底色淺藍 #DEEAF6，文字置中 12pt；左欄的詞也用淺藍底。短句練習的表頭是灰色 #E7E6E6。
- **＊註解**：橘色 #C55A11。
- **聲調紅線**：#FF7D80，約 0.75pt。

## 每頁密度（使用者要求和範本一致）

範本 5 份共 28 頁的量測結果：
- **純文字頁**：約 42–48 行、600–900 字，內容填到版心高度的 93–100%。
- **插圖頁**：12–18 張圖，填到 83–96%。
- **日文行距**：含ルビ一行約 23–26pt，產生器目前設定為 LINE_H = 25。
- **詞卡**：每列約 137pt 高，圖片寬約 100pt，幾乎填滿格子。
- **留白**：只有大段落結束時才會留白，例如課外補充結束、下一頁從「大家的日本語 L??」開始；其餘頁都排滿。

組版後逐頁檢查以下幾點：
- 有沒有頁面沒排滿、卻不是段落結束？
- 表頭有沒有和內容拆在兩頁？
- 詞和它的例句有沒有被分頁拆開？
- 有沒有一列因為內容很少卻占了很高的空間？

發現問題時，先分析原因再告訴使用者，一次調一頁。

## ルビ與紅線（使用者指定：用 Word 內建 ruby，遵守 JIS X 4051／W3C JLReq）

- **ルビ**：用 w:ruby。
  - 熟語ルビ逐字對應：note.json 寫成 `{割|わり}{引|びき}`。只有熟字訓才整組寫，例如 `{今日|きょう}`。數字整組寫，例如 `{10|じゅっ}`。
  - ルビ置中。ルビ比親字長時，親字兩側自動加空。
  - 日文段落開禁則處理，關閉中日、英數之間的自動加空，讓字位可以預測。
- **紅線**：做法和原版一樣，是另外畫的線條圖形（原版 PDF 裡的紅線是向量線段，不是文字格式），貼在ルビ上方。
  - 程式依字寬算出每一拍的水平位置；水平位置相對於行首字元，垂直位置相對於行頂。
  - 水平線代表該拍是高音；右端往下的折角代表「這拍高、下一拍低」。
  - 同一個語音片段內，連續的高音拍連成一條線。
  - 可以調整的參數在 build_note.py 開頭：LINE_H、PITCH_Y、PITCH_DROP、TAB_X、ILLUST_BOX。
- **限制**：在 Word 裡改字之後，紅線不會跟著移動，要改 note.json 重新產生。這點和原版手動畫線一樣。
- **預覽**：這個環境沒有原版字型，預覽要加 `--preview`。這會換成 IPAGothic 和它的字寬，讓 LibreOffice 預覽的紅線對得上；正式檔不要加。
- **Word 待確認**：Word 排ルビ和行高的方式可能和 LibreOffice 不同。使用者如果回報紅線偏移，只要調 PITCH_Y／TAB_X 這類參數，不用改內容。

## 版面陷阱（已在產生器處理，改程式時要注意）

- 頁面上相鄰的兩張表格中間沒有段落的話，會被合併成一張。
- 在儲存格裡放「巢狀表格日文行＋中文欄」，LibreOffice 會把它壓縮，所以例句表一律讓中文獨立成外層表格的一欄。
- pPr 的子元素要照 schema 順序插入（見 ppr_set），否則 Word 可能判定檔案損毀。
- 對照表整張設成 keepNext，避免拆頁；其他表格至少讓表頭和第一列留在同一頁。
