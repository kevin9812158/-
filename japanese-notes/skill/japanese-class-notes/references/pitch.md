# 聲調

要判讀原版講義上的紅線、做拆句時，用 `japanese-pitch-reader` skill（已安裝在使用者帳號）。這裡只放筆記產生需要的重點。

## 目前規則（使用者指定）

- 還沒有聲調資料的詞，一律先畫成 0 號音（平板），也就是 note.json 的 `accent_default: 0`，並在待確認清單列一條【高】。
- 聲調資料來自 JAPANESE UP 聲調 MCP（見下方「MCP 聲調資料」），拿到後把號數填進 `#n` 再重新產生。

## 標記

- **統一標記**（單字、例句通用）：`型（號數）：每拍高低`。號數＝在第幾拍之後下降。
  - 0：平板
  - 1：頭高
  - 1 < n < 拍數：中高
  - n＝拍數：尾高
- **怎麼數拍**：小寫的ゃゅょ併入前一拍；っ、ん、ー 各算一拍。
- **紅線的意思**：
  - 水平線＝該拍是高音。
  - 右側的下降角＝「這拍高、下一拍低」。
  - 範本上有時會簡化畫法，要依規則補回。
  - 完全沒有線＝待確認，不可以當成平板。
- **平板和尾高**：兩者詞末都是高音，差在後面接的助詞：平板後的助詞是高音，尾高後的助詞是低音。

## 拆句

- **語音片段**：實詞，各自有聲調。
- **接續文字**：は が を に へ で と の も から まで より か。跟著前一個片段走：前一段是平板，助詞就高；前一段有下降，助詞就低。
- **顯示**：接續文字歸在前一個片段後面，例如「年を｜取る」。
- **讀音**：は 讀 わ，へ 讀 え。
- **邊界**：標點是片段的邊界。
- 判斷不出來就標待確認，不要猜。

## MCP 聲調資料（JAPANESE UP！聲調查詢）

連接器在 claude.ai 的「自訂 → 連接器」設定；新增後要開新的工作階段才會載入。

**使用前**
- 先用 getPronunciationCollaborationStatus 確認同意狀態是 current。
- 查詢內容會在伺服器保存 90 天，供本人追溯與服務擁有者校訂；不要送機密或他人個資。

**查詢**
- 新的詞、句子用 analyzeJapanesePronunciation。課本題庫裡已有的詞用 getAuthorizedPronunciations。
- 少量查詢就好，不要整份逐字稿丟進去。
- 不要自行補齊未知的聲調，原始 JSON 照實保留。

**回傳欄位**
- `tokens[]`：詞法單位，は、から、ます 也會單獨成一個 token。每個 token 有：
  - `surface`
  - `reading`：整詞讀音，沒有逐字對應熟語ルビ，逐字切分由我們處理。
  - `moras`
  - `marks`：每拍的高低。0＝低，1＝高，2＝高且為該詞最後一個高拍。2 後面是否真的下降，平板和尾高的差別還要看片語層級，定義待伺服器確認。
  - `accent`：號數，可能是 null。
  - `status`：目前都是 predicted。
  - `warnings`：例如 phrase_accent_unresolved。
- 整筆查詢另有 `needsReview`、`reviewStatus`（目前都是 unreviewed）和 `warnings`。

**2026.10.08 測試的結果**
- 單字可以直接用：割引 0、勤める 3（和範本一致）、ご飯 1、食べろ 2。
- 句子還不夠：
  - 整句的 accent 都是 null。
  - 助詞一律回傳 0（「割引は」的 は 應該是高）。
  - 複合詞被拆開（八時、ガチョウ肉；ガチョウ肉 範本是 2 號，MCP 沒解出來）。
  - 同一個詞放在句中和單獨查，結果不同（割引 `[0,1,1,2]` vs `[0,1,1,1]`），而且沒有帶警告。

**轉成筆記**
1. tokens 要依「語音片段＋接續文字」重新組合，例如 始まり＋ます 合成一個片段、は 歸到前一個片段。
2. 號數有解出來的才填 `#n`；沒解出來的照規則處理，並列入待確認。
3. 句中助詞的高低如果依拆句規則補上，屬於「依規則推算」，要列【高】，而且要使用者同意這樣做。

**檢查流程（依風險分流，所有項目都保留）**
1. 把 MCP 原始 JSON 存檔，執行 `python3 scripts/mcp_pending.py 結果.json --ref 已知資料.json`。它只依 MCP 欄位與對照資料判斷等級：
   - 有 warnings、accent null 或 needsReview → 高
   - 和範本或已知資料不一致 → 高
   - 同一詞在不同查詢的 marks 不一致 → 高
   - 其餘 → 低
   輸出可以直接放進 pending.lines。
2. 沒有警告不代表正確。要保留抽樣比對範本的步驟，把範本紅線讀出來的號數放進 `--ref`。
3. 依規則補上的部分（例如句中助詞），撰寫時另外列為【高】。

**回饋修正**
- 審閱後的修正要經使用者逐筆同意，才用 submitPronunciationFeedback 送回伺服器。
- 送之前先列出要送的修改內容和用途。
- 只送相關的修正和依據，不送整段對話。
- 沒有同意的就保持未回報。
- 有警告的項目，就是要審的清單。
